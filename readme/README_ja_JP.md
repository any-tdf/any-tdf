## はじめに

Any TDF は、Svelte、React、Vue 向けのモバイルファーストなコンポーネントシステムです。3 つのライブラリは、製品の挙動、ビジュアル言語、テーマ、ロケールデータ、公開型、ドキュメント構成、アクセシビリティ規則を共有しつつ、各フレームワーク固有のレンダリングモデルと構成方法を維持します。

これはクロスフレームワークのラッパーでも、アダプターの背後に隠れた単一ランタイムでもありません。STDF は Svelte コンポーネント、Snippet、Action、Transition を、RTDF は React コンポーネント、Props、レンダー関数、Hook、Provider を、VTDF は Vue コンポーネント、スロット、イベント、Composition API を提供します。

## Any TDF を選ぶ理由

- 60 個のモバイルコンポーネントが揃い、各フレームワークに自然な API と予測可能な挙動を提供します。
- ダークモード、実行時切り替え、カスタムテーマ、再利用可能なセマンティックカラーに対応する共有 Tailwind CSS テーマシステム。
- 60 以上の組み込みロケールと、中国語・英語のガイド、API リファレンス、コンポーネント例。
- TypeScript ファーストのパッケージエクスポート、SSR、オンデマンドインポート、共通のアクセシビリティ動作。
- Svelte ネイティブのモーションセマンティクスと、それに対応する React・Vue モーションパッケージ。
- 統合プロジェクトジェネレーター、SVG スプライトと Markdown プラグイン、オフライン AI Skills、VS Code 拡張機能。
- 3 つの実装を揃えるコントラクト、パッケージ、ルート、ブラウザー、ビジュアルチェック。

## クイックスタート

> 次世代コンポーネントファミリーは現在 npm の `alpha` タグで公開されています。2 つの Vite プラグインは安定版の `latest` タグを使用します。

対話形式で TypeScript プロジェクトを作成します。

```sh
bun create any-tdf@alpha
```

フレームワークとスターターを直接指定することもできます。

```sh
bun create any-tdf@alpha my-app -f svelte -t sktt -b lucide
bun create any-tdf@alpha my-app -f react -t vrtt -b phosphor
bun create any-tdf@alpha my-app -f vue -t vrtt -b tabler
```

ジェネレーターは、Vite と SvelteKit のテンプレート、TypeScript、Tailwind CSS または UnoCSS、複数のアイコン方式、組み込みアイコンライブラリ、単一・複数テーマ設定を提供します。すべてのオプションは [`create-any-tdf` リファレンス](../packages/create-any-tdf/README.md)を参照してください。

既存のアプリケーションにコンポーネントライブラリを追加します。

```sh
bun add stdf@alpha svelte tailwindcss
bun add rtdf@alpha react react-dom tailwindcss
bun add vtdf@alpha vue tailwindcss
```

使用するフレームワークの行だけをインストールしてください。共有 Any TDF ランタイム依存関係は各パッケージが自動的にインストールします。スタイルシートのインポート、テーマ設定、コンポーネント、移行ガイドは各公式サイトを参照してください。

## 共有アーキテクチャ、ネイティブレンダリング

共有レイヤーの責務は意図的に限定されています。`@any-tdf/common` は、再利用可能な状態導出、テーマ、ロケールデータ、SVG データ、型、小規模なプラットフォームユーティリティを担当します。STDF、RTDF、VTDF はこれらのコントラクトを利用しながら、各フレームワークのプリミティブでレンダリングします。

この分離により、次の利点が得られます。

- 各フレームワークで馴染みのあるコンポーネント構文、イベント、スロット、Children、構成方法。
- 一貫したコンポーネント機能、命名、テーマ、ロケール動作、モバイル操作。
- 独立した npm パッケージ、ドキュメントサイト、Demo、リリースノート、フレームワーク更新。
- アプリケーションコードにクロスフレームワークレンダラーや追加の互換ランタイムは不要です。

## VS Code 拡張機能

[Any TDF for VS Code](../extensions/vscode-extension/README.md) は、STDF、RTDF、VTDF のホバードキュメントとコンポーネント API 補完を提供します。最も近い `package.json` を検出し、該当ライブラリだけを有効化します。Svelte、JSX、TSX、Vue ファイルと、中国語・英語の API ドキュメントに対応します。

拡張機能のソース、パッケージ、公開チェックはこの Monorepo で管理されています。ローカル VSIX をビルドするには次を実行します。

```sh
bun run --filter stdf-vscode-extension package
```

## Monorepo 開発

このリポジトリは Bun Workspaces、Turborepo、Changesets、単一のルートロックファイルを使用します。開発には Bun と Node.js を使用し、依存関係はリポジトリルートからのみインストールします。

```sh
bun install --frozen-lockfile
bun run check
bun run test
bun run build
bun run verify
```

Any TDF ポータル、または各フレームワークのサイトと Demo を同時に起動します。

```sh
bun run dev:any-tdf
bun run dev:stdf
bun run dev:rtdf
bun run dev:vtdf
```

リポジトリ全体でよく使うコマンド：

| コマンド                 | 用途                                                           |
| ------------------------ | -------------------------------------------------------------- |
| `bun run generate`       | フレームワーク、ドキュメント、バージョン、拡張データを再生成。 |
| `bun run generate:check` | 生成ファイルがソースと一致することを確認。                     |
| `bun run quality:check`  | Monorepo をビルドし、フォーマットと lint を確認。              |
| `bun run verify:browser` | 実ブラウザーで Demo とドキュメント操作を検証。                 |
| `bun run changeset`      | 次回リリースに含まれるパッケージ変更を記録。                   |

## リポジトリ構成

- `apps`：ドキュメントサイト、コンポーネント Demo、共有サイトコード。
- `packages`：共有コア、フレームワークライブラリ、Vite プラグイン、Motion・Confetti ランタイムとパッケージ内ドキュメント、AI Skills、`create-any-tdf`。
- `content`：生成された STDF、RTDF、VTDF のコンポーネントとガイド。
- `extensions`：Any TDF VS Code 拡張機能。
- `scripts`：リポジトリ全体の生成、検証、パッケージ化、リリースツール。
