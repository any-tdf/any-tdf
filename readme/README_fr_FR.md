## Introduction

Any TDF est un système de composants mobile-first pour Svelte, React et Vue. Ses trois bibliothèques partagent le comportement produit, le langage visuel, les thèmes, les données de langue, les types publics, la structure documentaire et les règles d’accessibilité, tout en préservant le modèle de rendu et les habitudes de composition propres à chaque framework.

Il ne s’agit ni d’un wrapper inter-frameworks ni d’un runtime unique dissimulé derrière des adaptateurs. STDF expose les composants, snippets, actions et transitions Svelte ; RTDF propose les composants, props, fonctions de rendu, hooks et providers React ; VTDF fournit les composants, slots, événements et composables Vue.

## Pourquoi choisir Any TDF

- 60 composants mobiles alignés, avec des API natives pour chaque framework et un comportement prévisible.
- Un système de thèmes Tailwind CSS partagé avec mode sombre, changement à l’exécution, thèmes personnalisés et couleurs sémantiques réutilisables.
- Plus de 60 langues intégrées, ainsi que des guides, références d’API et exemples de composants en chinois et en anglais.
- Exports de paquets centrés sur TypeScript, SSR, imports à la demande et accessibilité partagée.
- Sémantique de mouvement native de Svelte avec des paquets correspondants pour React et Vue.
- Générateur de projets unifié, plugins SVG Sprite et Markdown, AI Skills hors ligne et extension VS Code.
- Vérifications des contrats, paquets, routes, navigateurs et rendus visuels pour garder les trois implémentations alignées.

## Démarrage rapide

> La nouvelle génération de composants est actuellement publiée sur npm avec le tag `alpha`. Les deux plugins Vite utilisent le tag stable `latest`.

Créez un projet TypeScript de manière interactive :

```sh
bun create any-tdf@alpha
```

Vous pouvez également indiquer directement le framework et le modèle :

```sh
bun create any-tdf@alpha my-app -f svelte -t sktt -b lucide
bun create any-tdf@alpha my-app -f react -t vrtt -b phosphor
bun create any-tdf@alpha my-app -f vue -t vrtt -b tabler
```

Le générateur fournit des modèles Vite et SvelteKit, TypeScript, Tailwind CSS ou UnoCSS, plusieurs stratégies d’icônes, des bibliothèques d’icônes intégrées et des configurations à thème unique ou multiple. Consultez toutes les options dans la [référence `create-any-tdf`](../packages/create-any-tdf/README.md).

Pour ajouter une bibliothèque de composants à une application existante :

```sh
bun add stdf@alpha svelte tailwindcss
bun add rtdf@alpha react react-dom tailwindcss
bun add vtdf@alpha vue tailwindcss
```

Installez uniquement la ligne correspondant à votre framework. Chaque paquet installe automatiquement ses dépendances d’exécution Any TDF partagées. Consultez le site correspondant pour les imports de styles, les thèmes, les composants et les guides de migration.

## Architecture partagée, rendu natif

La couche partagée a une responsabilité volontairement limitée. `@any-tdf/common` gère la dérivation d’état réutilisable, les thèmes, les données de langue et SVG, les types et de petits utilitaires de plateforme. STDF, RTDF et VTDF consomment ces contrats, mais effectuent le rendu avec les primitives de leur propre framework.

Cette séparation apporte :

- Une syntaxe de composants, des événements, slots, children et habitudes de composition familiers dans chaque framework.
- Des capacités, noms, thèmes, langues et interactions mobiles cohérents.
- Des paquets npm, sites de documentation, Demos, notes de version et mises à jour de frameworks indépendants.
- Aucun moteur de rendu inter-frameworks ni runtime de compatibilité supplémentaire dans le code applicatif.

## Extension VS Code

[Any TDF for VS Code](../extensions/vscode-extension/README.md) fournit une documentation au survol et l’autocomplétion des API de composants pour STDF, RTDF et VTDF. Elle détecte le `package.json` le plus proche, active uniquement la bibliothèque correspondante, comprend les fichiers Svelte, JSX, TSX et Vue, et affiche la documentation d’API en chinois ou en anglais.

Le code source de l’extension ainsi que ses vérifications d’empaquetage et de publication sont maintenus dans ce Monorepo. Pour créer un VSIX local :

```sh
bun run --filter any-tdf-vscode-extension package
```

## Développement du Monorepo

Le dépôt utilise Bun Workspaces, Turborepo, Changesets et un seul fichier de verrouillage à la racine. Le développement utilise Bun et Node.js. Installez les dépendances uniquement depuis la racine du dépôt.

```sh
bun install --frozen-lockfile
bun run check
bun run test
bun run build
bun run verify
```

Lancez le portail Any TDF, ou le site et la Demo d’un framework ensemble :

```sh
bun run dev:any-tdf
bun run dev:stdf
bun run dev:rtdf
bun run dev:vtdf
```

Commandes courantes à l’échelle du dépôt :

| Commande                 | Rôle                                                                               |
| ------------------------ | ---------------------------------------------------------------------------------- |
| `bun run generate`       | Régénère les données de frameworks, documentation, versions et extension.          |
| `bun run generate:check` | Vérifie que les fichiers générés correspondent à leurs sources.                    |
| `bun run quality:check`  | Construit le Monorepo et vérifie le formatage et le lint.                          |
| `bun run verify:browser` | Vérifie les interactions des Demos et de la documentation dans un vrai navigateur. |
| `bun run changeset`      | Décrit les modifications de paquets pour la prochaine publication.                 |

## Structure du dépôt

- `apps` : sites de documentation, Demos de composants et code de site partagé.
- `packages` : cœur partagé, bibliothèques de frameworks, plugins Vite, runtimes Motion et Confetti avec documentation par paquet, AI Skills et `create-any-tdf`.
- `content` : composants et guides STDF, RTDF et VTDF générés.
- `extensions` : extension Any TDF pour VS Code.
- `scripts` : outils globaux de génération, validation, empaquetage et publication.
